# Jaskinia v6.1: the foundation (18 Oct 2026, evening)

On 18 Oct the owner stopped the work and asked for a look from above. His sense was that Jaskinia was losing
coherence, meaning, stability and completeness.

The look from above found:
- no single "what for";
- building faster than he can experience;
- a stack of unaccepted versions;
- cracks in the foundation;
- Studio and Jaskinia drifting apart;
- many agent lines with nobody holding the whole.

With him we wrote the **[Jaskinia compass (issue #5)](https://github.com/Jozzpoly/Jozz-Cave-Workbench/issues/5)**. Every
agent reads it first, and changes go there rather than into separate START_HERE files.

v6.1 adds nothing new on top. It makes what exists trustworthy (compass point 4: nothing important disappears without
the owner knowing, and everything has an address). Each item below answers an audit by GPT or Medium, or a defect
found in the code.

## What changed

**Several tabs merge instead of overwriting** (`15-store.js`, `50-shell.js`).

v6 wrote a tab's whole copy on every hide. An older tab, closed last, overwrote the layouts and notes made in a newer one.

Now:
- A tab writes only after it changed something (`dirty`).
- Every written state names itself and the state it grew from (`rev`, `par`).
- Other tabs take a write in through the `storage` event, without restarting running windows. They merge it three ways against the state it grew from:
  - **Layouts** merge window by window.
  - **Notes** keep the newer text.
  - **Views, saved states and the trash** merge item by item.
- When the same layout was rearranged in two tabs at the same moment, or the same note was edited in both:
  - this tab's version stays;
  - the other version goes to an automatic copy;
  - the owner is told once.
- A storage wiped by another page at this address is written back by the open tab.
- Note editors (the Notes window and wall notes) write back only text that was typed in them. An older text on screen never overwrites a newer one on blur or on a redraw.

**Addresses** (`59-adresy.js`).

| Address | What it does |
|---|---|
| `#repo~Name` | Selects the project. From outside, it also puts a card that follows the selection on screen. |
| `#m~id` | Shows the material in the Materiały window. |
| `#uklad~id` or `#uklad~Name` | Switches to that layout. |
| `#agenci`, `#notatki`, `#materialy`, `#historia`, `#wiedza`, `#mapa` (or `#panorama`), `#sciana`, `#statystyki` | Opens that window. |

These addresses work:
- when the page is opened with one;
- when the address is typed;
- from links inside windows ("Pełna historia" in Puls works again).

The address follows the selected project through `replaceState`. While the phone's Back guard stands, the address is left alone, so Back still only closes a sheet.

**"Dla agentów"** (window type `agenci`, address `#agenci`).

The same Jaskinia as plain text, for GPT reading the owner's tab through Opera, for Codex and for Claude. It shows:
- what is on screen;
- the owner's notes, newest first, including notes without a window (this is where he leaves words for agents);
- the materials with their addresses;
- the Library's brief.

It only reads.

**Materials** (`57-materialy.js`, `58-api.js`).
- **Settings revisions.** Every turn or scale change adds a numbered revision and keeps the earlier ones:
  - `Jaskinia.materialy.settings(id)` lists them;
  - `object(id, {set: n})` gives the look a place was built with;
  - `object(id)` gives the newest;
  - `userData.set` says which one.

  A place can pin its look or follow the newest. Nothing changes under it silently.
- **Folder import by path.** A model's companion files are the ones at the path the model names, else the nearest with that name. Two `texture.png` in `dom/` and `wieza/` no longer mix.
- **No leftovers.** A model that cannot be read leaves no bytes behind.
- **Shared library across tabs.** Every tab sees the same library: a change in one tab tells the others (BroadcastChannel).
- **`.vox` wording.** Product texts no longer single out `.vox`. The owner clarified that the `.vox` rule was about Claude searching his disk, not about what Jaskinia may read. Files of other kinds are simply not read by a folder import.

## Checks

`node tools/jk61_test.mjs` runs 29 checks in SwiftShader:
- **two tabs in one browser context:**
  - one tab takes in the other's window and note without a reload;
  - a tab with nothing new writes nothing;
  - changes made at once in two tabs both stay;
  - the same note in both tabs keeps the newer text, and the other text waits in a copy;
  - the same layout rearranged in both tabs ends as one valid shape;
  - a wiped storage is written back;
  - a new tab opens on the merged state;
- **addresses:**
  - an address opened from outside, typed, or clicked inside a window;
  - an unknown address says so;
- **the agents window** with the owner's notes;
- **materials:**
  - folder paths;
  - the other tab seeing new materials;
  - settings revisions;
  - an unknown material address;
  - no leftover bytes.

The older suites stay green:
- `jk_test` 52;
- `jk2_test` 76;
- `jk2_chaos 400 7` (800 random steps, desk and phone, with reloads);
- `jk4_test` 61;
- `jk5_test` 43;
- `jk6_test` 51.

Three older checks wrote the store directly and called `persistNow()`. They now call `persist()` first, as the app does, because an unchanged tab no longer writes.
