## What was measured

Run it again with:

```
node tools/probes/hosting.mjs
```

The probe uses a blank host page in place of Jaskinia and a tiny page in place of a lab or tool.

Conditions:
- Playwright's own Chromium (`playwright` 1.56), headless.
- Storage partitioning is switched back on. Playwright turns it off by default (`ThirdPartyStoragePartitioning` in `chromiumSwitches.js`); Chrome ships with it on.
- Nothing here was checked in the owner's Opera or on a phone.

**1. `requestAnimationFrame` calls per second while Jaskinia hides the window.** Timers keep running in every case.

| how Jaskinia hides it | same origin | other origin |
|---|---|---|
| visible | 60 | 60 |
| `display:none` (another layout) | 60 | **0** |
| `visibility:hidden` (behind a maximized window, phone) | 60 | 60 |
| offscreen | 60 | **0** |
| `opacity:0` | 60 | 60 |

Hiding and showing changed neither the page's viewport nor fired `resize`. Only a real change of size does that.

**2. What a framed tool can still reach.** Before each row, the tool saved `standalone` while opened on its own.

| where the tool runs | sees its standalone save | export (download) | import (file input) | opens a folder (File System Access) |
|---|---|---|---|---|
| on its own, top level | yes | yes | yes | yes, a picker opens |
| framed, same origin (today on Pages) | yes | yes | yes | yes |
| framed, same site, other origin | yes | yes | yes | **no:** "Cross origin sub frames aren't allowed to show a file picker" |
| framed, other site (e.g. `*.pages.dev`, a public suffix like `github.io`) | **no**, empty | yes | yes | **no** |

**3. A downloaded Jaskinia (`file://`) framing the tool.**
- First visit: the tool sees nothing.
- Second visit: it sees what it saved during the first.
- The same tool opened on its own keeps `standalone`.

So the framed copy and the standalone copy are two saves that drift apart without anyone noticing.

What follows from this:
- **Pages today.** Jaskinia and the games share one origin. Games keep animating and keep their saves. The price: no isolation, so a game can read Jaskinia's notes (M2), and every copy of a game uses one save.
- **Separating origins for isolation changes two behaviours at once.**
  - Hidden windows stop animating. The fix is Jaskinia's: park hidden windows instead of using `display:none`.
  - A framed game stops seeing its standalone save, unless Jaskinia and the games share one site, i.e. one owned domain with subdomains.
  - A folder picker is then refused inside the frame either way.
- **A downloaded Jaskinia is already "another site" to every game.**
- **Our own checks.** Any PASS about storage, origins or hidden frames from default Playwright, GPT's CI and these suites included, must say which flags it ran with. The owner's browser decides.

## Can Jaskinia host independent instruments without imposing on them?

Two questions reached the Jaskinia line this evening:
- **The Feniks line**, after building a small authoring probe, asked whether Jaskinia can take such instruments without imposing a lifecycle, units of space or a way of storing work.
- **The Studio line** ([reassessment, `f650d24`](https://github.com/Jozzpoly/Feniks-Studio/blob/f650d24287e7362ebe921720b6b2125855cd8e9c/docs/research/2026-10-16-wspolny-warsztat.md)) asked how much change real authoring needs in Jaskinia, and whether the work stays usable outside Jaskinia's global state.

Each answer below is judged by the same criteria the Studio line applies to every route.

**What Jaskinia imposes today**
- **Lifecycle.** Jaskinia does not reload an instrument except when the owner asks, or when the interface language changes, which rebuilds Jaskinia (a debt). It does not yet keep an instrument alive: an instrument from another origin in a hidden layout stops animating. Fixing that is Jaskinia's job. Resting stays the instrument's own choice (`visible`).
- **Units of space.** None. Jaskinia only gives the page a viewport that changes with the window, and an instrument that sizes its world by its viewport changes its world. Instruments should not do that. Jaskinia can later offer a fixed-size, scaled view.
- **Storage of the work.** Jaskinia never reads or writes an instrument's storage; its own store keeps only the window and the address. But where Jaskinia is hosted decides which storage the instrument sees and whether it may open a folder (table 2). Hosting is therefore a joint decision with whoever designs the storage of the work.
- **Keys.** Keys typed inside a framed instrument never reach Jaskinia's shortcuts. The instrument hears them only after a click inside it.
- **Identity.** A `przyrzad` window runs its own address. A `gra` window still follows the selection until it is pinned (seam 1).

**Two ways to put an authoring tool in Jaskinia**
- **(a) Its own page, framed as an instrument.**
  - This is the same tool as a narrow standalone tool, in two places. The Studio line's check ("open and change the work without Jaskinia's globals and windows") holds by construction, because the page also runs on its own.
  - Jaskinia adds:
    - composing it beside other instruments;
    - remarks pinned to its state;
    - later, a second view of the same work in another window. The tool would keep both views together inside its own origin, for example with a `BroadcastChannel` or a worker.
  - Jaskinia costs it the placement limits in table 2, plus Jaskinia's seams 1, 2 and 5.
- **(b) A window type inside Jaskinia's own page.** It inherits every seam of the shell:
  - shared DOM and keys;
  - the whole-store `localStorage`;
  - layout undo;
  - the relaunch on a language change.

  It also ties the work to Jaskinia's globals. I would not take (b) for a first authoring trial.

**Jaskinia's work before hosting such a guest**, small to medium:
- instance identity and placement;
- parking hidden windows;
- giving focus to a starting or clicked instrument;
- a "second view beside" action;
- F1 for the contract.

None of it touches the tool's work format.

**What Jaskinia cannot offer**
- Inside claude.ai no other site can be framed.
- A downloaded Jaskinia gives framed tools a separate save and no folder access.

**Not measured yet**
- Whether a folder handle the tool obtained on its own, kept in its IndexedDB, still works when the same tool is framed on the same site.
- The Storage Access API.
- Anything in Opera, and phones.

## The order once building resumes

1. **Instance and launch.**
   - Take GPT's launch-hook change (`c00e3a4`) as is, credited.
   - A new game opens beside the running ones.
   - Play on a game that is already running brings its window forward.
   - A second copy of a game is a deliberate action.
   - A game window pins itself once its game starts.
   - Checks look at placement and pixels, not only state.
2. **Life is not the view.**
   - Hidden windows are parked so they keep painting, never with `display:none`.
   - Each instrument may ask for a fixed-size view.
   - `visible` stays advice to the instrument.
3. **Trust.**
   - The drop-in answers only the parents a lab lists, and answers `file://` only if the lab allows it.
   - The hosting decision belongs to the owner and GPT, made with table 2.
   - Until then, Jaskinia at the shared origin holds nothing private.
4. **Saves.** F2: a namespaced schema with an explicit migration. Also the D7 items:
   - backup dedupe ignores views;
   - the trash silently stops at 200 items;
   - the "Cała Jaskinia" export is not disaster recovery.
5. **Keys.**
   - Shortcuts respect `defaultPrevented` and the focused tool.
   - A starting or clicked instrument gets focus.
   - **JV steering.** GPT showed that JV's steering adapter maps only A/D and the arrows, while throttle and brake are separate paths. Before claiming a cause, separate:
     - which build ran;
     - which controls it expects;
     - key reception;
     - steering;
     - throttle.

     Jaskinia launches whatever Pages address the chosen repository records. JV has an experiment and a public repository, each with its own Pages, and Jaskinia does not know which build is the accepted one. That is the older "explicit entrances" debt.
6. **Then** the first real lab speaking the contract, and the first authoring tool as a guest.
