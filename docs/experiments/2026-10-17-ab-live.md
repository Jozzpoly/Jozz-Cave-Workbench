# Jaskinia A/B — independent experimental branch, 17 October 2026

**Source:** `experiment/gpt-live-comparison-2026-10-17`, created from Opus's **v5** head `96c2a1c`.
**Status:** experimental feature, **not an Owner-approved product**, **not merged**, **not deployed**.
**Purpose:** turn Jaskinia's existing instrument telemetry into a usable live experiment: two independently running worlds can be observed on the same wall-clock axis, and the raw sample trail can be taken out for investigation.

## User experience

In an empty Jaskinia window choose **Na żywo → Porównanie**. Run two `Przyrząd` windows, for example two independent instances of the built-in `Piłki` demo. In the comparison window:

- choose the exact instrument instance for A and B (not just a repository name);
- choose which numerical signal from each side to observe;
- choose 10 seconds, 60 seconds or 5 minutes;
- see both streams on one wall-clock axis and their current readings;
- download a CSV with provenance (side, capture time, instance id, lab name, address, signal name, sample time, value).

No lab installation, protocol extension, controller interception or cloud backend is required. The existing v5 `LIVE` registry and signal buffers are read **without modification**. Changing the comparison never reloads either lab. The comparison only reads instrument entries in the **current Jaskinia layout**.

## Honest limits

1. **Observation, not scientific controlled A/B.** This does not synchronize inputs, starting time, simulations, random seeds, frames or world state. A common signal name is not proof of common units or semantics.
2. A live instrument can be temporarily invisible or its animation throttled by the browser. CSV records each actual signal timestamp; it does not pretend missing samples were observed.
3. It compares two **independent runtimes**, not two cameras on one shared simulation. One world with many views is a separate research seam.
4. A chart and CSV cannot reconstruct a lab's full state or its physics. The instrument's own saves remain its responsibility.
5. This is intentionally **not** a patch for v5's game-window reuse, unsafe same-origin embedding, bridge-parent trust, legacy storage overwrite, JV keyboard Owner FAIL or cross-origin hidden-frame freeze. Opus's v6 planning addresses some of these; do not silently promote the present trial as fixing them.
6. CSV is an explicit user download and includes the lab URLs. No new automatic telemetry upload/storage is introduced. Lab-supplied CSV text fields are guarded against formula execution.
7. A public Pages same-origin preview is not a private safe workspace. Do not put confidential state in these labs before trust boundaries are addressed.

## Verification / acceptance gates

- **Source syntax:** standalone new JS parsed in the JS engine at creation.
- **Automated browser:** `npm ci && npx playwright install chromium && npm run jaskinia && node tools/jk6_compare_test.mjs`. Tests two actual running built-in demo iframes and populated telemetry, on-screen plot, user CSV download, duplicate-source refusal and no lab restarts after selection.
- **v5 regression:** `node tools/jk5_test.mjs`; the existing test probes preserve the independent Opus instrument contract.
- **Visual:** inspect desktop screenshot from the experiment, then check actual owner interaction on a narrow screen. A passing CI screenshot is not Owner feel PASS.
- **Owner experience:** the real qualification is whether comparing two active experiments is pleasurable and useful compared with two browser tabs + separate data, without breaking game controls or distracting from play.
- **Promotion:** do not merge into v5/Opus PR by inertia. Treat as a candidate donor; adapt to whatever v6 runtime/instance identity actually ships.

## Future hypotheses deliberately not implemented

- Two physically separate simulations responding to one explicit **synchronized stimulus**; this will require opt-in lab-side semantics and determinism contracts rather than generic synthetic key injection.
- One world, two lenses: same simulation state observed through a player camera, physics inspector or autonomous agent perception.
- Persistent experiments with replayable initial conditions, comparison traces and owner-created parameter variations. Never claim replay equivalence without a lab-specific contract.
- Connections between worlds; value must be demonstrated first with a real two-sided mechanic rather than an ornamental transfer animation.
